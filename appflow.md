## 1. System Overview & Contextual Primer for AI Models

This document defines the end-to-end execution flow of **QuantaCare**, a hybrid quantum-classical machine learning platform designed for early disease risk prediction. The architecture follows a high-performance **Modular Monolith**pattern using **Python and FastAPI**.

For AI agents, code generation models, or automated orchestration tools parsing this architecture: **all computational steps within the core pipeline execute synchronously in-memory** within a single Python runtime to eliminate network-hop latencies during training loops. External communication is strictly isolated to the entry point (FastAPI request-response) and the retrieval layer (**Pinecone** cloud vector search).

## 2. Complete Execution Flow (Step-by-Step State Machine)

```
[1. Client / UI] 
       │ (HTTP POST /predict with JSON payload)
       ▼
[2. FastAPI & Pydantic Validation] ──(Rejects malformed data with 422)
       │
       ▼
[3. Classical Data Engineering] (Sanitization & Normalization)
       │
       ▼
[4. Processed Feature Vector] (Structured floating-point numerical array in local RAM)
       │
       ▼
[5. Quantum Encoding] (Feature Mapping via $R_x, R_y$ rotation gates)
       │
       ▼
[6. Quantum Circuit Execution] (Parametrised Quantum Circuit via PennyLane/Qiskit)
       │
       ▼
[7. Quantum Probability Measurement] (Extracting state probabilities)
       │
       ▼
[8. Classical Optimizer Loop] (COBYLA/Adam gradient updates in local RAM)
       │
       ▼
[9. Trained Hybrid QML Inference] ──(Queries Pinecone Cloud Vector DB)
       │
       ▼
[10. Clinical Output & Reporting] (Color-coded risk severity score + Encrypted Summary Report)
```

## 3. Detailed Stage-by-Stage Functional Specification

### Step 1: Client Ingestion Request

- **Actor:** Frontend Web/Mobile Application (Clinician user interface).
    
- **Action:** Submits manual patient clinical vitals (e.g., age, biomarkers, physiological metrics) via an HTTP `POST`request to `/predict`.
    

### Step 2: FastAPI & Pydantic Validation

- **Component:** FastAPI Application Layer with Pydantic schemas.
    
- **Logic:** Intercepts incoming HTTP data. Automatically validates data types, checks for missing parameters, and enforces clinical boundary ranges.
    
- **State Change:** If validation fails, halts execution and returns a `422 Unprocessable Entity` error. If valid, passes the raw dictionary into memory.
    

### Step 3: Classical Data Engineering & Sanitization

- **Component:** Data Preprocessing Module.
    
- **Logic:** Cleans missing or null fields, strips malicious payload strings, and normalizes raw numerical values into standard continuous ranges [0,1].
    

### Step 4: Processed Feature Vector

- **Component:** In-Memory Array Representation.
    
- **Logic:** Stores the cleaned, structured array of numerical values generated by classical data engineering, holding them primed and formatted for mathematical translation into quantum space.
    

### Step 5: Quantum Encoding (Feature Mapping)

- **Component:** QML Interface Layer (PennyLane / Qiskit).
    
- **Logic:** Takes the processed feature vector and maps it into a quantum state vector within Hilbert space using parameter-shift-rule compatible rotation gates (Rx​, Ry​) to assign classical variables to virtual qubit rotation angles.
    

### Step 6: Quantum Circuit Execution (Parametrised Quantum Circuits - PQC)

- **Component:** Quantum Simulation Engine.
    
- **Logic:** Executes variational quantum circuits (VQCs) locally in CPU memory. Evaluates complex non-linear feature interactions using quantum superposition and entanglement principles.
    

### Step 7: Quantum Probability Measurement

- **Component:** Measurement Operator.
    
- **Logic:** Measures the expectation values or computational basis state probabilities of the terminal qubits, generating a raw probability distribution matrix.
    

### Step 8: Classical Optimizer Loop (Hybrid Optimization)

- **Component:** Classical Optimization Module (SciPy / COBYLA or PyTorch).
    
- **Logic:** Evaluates the quantum probability output against target loss metrics, computing gradients and iteratively updating circuit weight parameters locally in RAM until convergence.
    

### Step 9: Trained Hybrid QML & Pinecone Semantic Search

- **Component:** Cloud Retrieval Layer (**Pinecone**).
    
- **Logic:** Once the model infers a prediction vector, the system formats an embedding query and executes an API call to **Pinecone**. It performs a cosine similarity search against pre-indexed, anonymized historical patient vectors and clinical guidelines to pull context.
    

### Step 10: Clinical Output & Encrypted Summary Generation

- **Component:** Reporting & Presentation Layer.
    
- **Logic:** Translates mathematical outputs into a definitive risk classification mapped to visual severity tiers (Low, Moderate, High) with explicit color hex codes. Aggregates the risk score, confidence percentage, and Pinecone-retrieved medical context into an encrypted, clinician-ready summary report returned as a JSON response.
